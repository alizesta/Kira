# سرورهای MCP و ایجنت‌های مستقل

کد: `kira/mcp/` (`config.py`، `client.py`، `hub.py`، `agents.py`). بدون وابستگی جدید؛ فقط کتابخانه‌ی استاندارد.

## راه‌اندازی
1. فایل `kira_mcp.json` را در پوشه‌ی داده‌ی Kira (کنار `settings.json`) بسازید؛ نمونه: `docs/kira_mcp.example.json`.
2. برنامه را دوباره اجرا کنید. اگر فایل نباشد هیچ اتفاقی نمی‌افتد. برای خاموش کردن کامل: `"mcp_mode": "off"` در تنظیمات.
3. در چت بنویسید «وضعیت mcp» تا `mcp_info` خطاها را نشان دهد.

## سرورهای MCP
- انتقال: `command` + `args` (stdio) **یا** `url` (HTTP). ابزارها با نام `server__tool` در همان Tool Registry ثبت می‌شوند.
- فقط **خود کاربر** فایل را می‌نویسد؛ هیچ ابزاری برای ثبت سرور توسط مدل نیست.
- سطح ابزار فقط از فایل می‌آید: `levels` برای هر ابزار، وگرنه `default_level`، وگرنه **sensitive** (هر بار تأیید صریح). علامت‌های خود سرور (مثل readOnlyHint) نادیده گرفته می‌شوند.
- ابزار سطح پایین‌تر از sensitive فقط وقتی اجرا می‌شود که پیام فعلی کاربر نام سرور یا `keywords` را بگوید.
- محیط زیرپروسه فقط `env` فایل + چند متغیر سیستمی است؛ کلیدهای API و `settings.json` هرگز منتقل نمی‌شوند. `shell=True` نیست.
- هر درخواست خود سرور به ما (sampling، roots و ...) رد می‌شود.
- توضیح و خروجی سرور پاک‌سازی، redact و بریده می‌شود و «داده‌ی غیرقابل‌اعتماد» علامت می‌خورد.
- `allow` / `deny` / `max_tools` اندازه‌ی کاتالوگ را برای مدل‌های کوچک محدود می‌کنند.
- timeout بدون retry (ممکن است کار اجرا شده باشد). پس از خطا، ۳۰ ثانیه بعد دوباره تلاش می‌شود.

## ایجنت‌های مستقل
قرارداد HTTP/JSON (سمت ایجنت جدا از Kira است): `GET /health`، `POST /ask`، `GET /status/{id}`، `POST /answer/{id}`، `POST /stop/{id}`. توکن اختیاری از متغیر محیطی `token_env` خوانده می‌شود، نه از فایل.
ابزارها: `agent_ask`، `agent_status`، `agent_answer`، `agent_stop`، `agent_health`.
- `agent_ask` سطح sensitive است (تأیید کاربر)، retry ندارد و `user_quote` می‌خواهد که باید عین بخشی از پیام همان نوبت کاربر باشد.
- `agent_answer`: چیزی که به ایجنت می‌رسد خودِ نقل‌قول تأییدشده‌ی کاربر است، نه متن ساخته‌ی مدل. برای approval باید کاربر صریح تأیید/رد کند.
- سلامت ایجنت قبل از واگذاری بررسی می‌شود (کش ۳۰ ثانیه). اگر آماده نباشد کاری ساخته نمی‌شود.
- Idempotency: کار باز با همان ایجنت و همان متن دوباره ساخته نمی‌شود.
- کارها در `kira_jobs.json` می‌مانند؛ با بستن برنامه یا تغییر route از بین نمی‌روند. یک poller پس‌زمینه وضعیت را به‌روز می‌کند.
- خروجی ایجنت داده‌ی غیرقابل‌اعتماد است و نمی‌تواند سطح دسترسی را تغییر دهد.

## محدودیت‌ها
- اعلان خودکار پایان کار در UI نیست (UI تغییر نکرد)؛ نتیجه وقتی خوانده می‌شود که کاربر بپرسد یا مدل `agent_status` بزند.
- HTTP MCP فقط پاسخ JSON یا یک پاسخ SSE را می‌فهمد؛ OAuth ندارد.
- ورودی‌های تو در تو (object/array) بدون اعتبارسنجی عمیق به سرور می‌روند؛ به همین دلیل پیش‌فرض sensitive است.

## نیاز به اعتبارسنجی روی Windows
1. اجرای یک سرور واقعی با `npx` (resolve شدن `npx.cmd`) و ثبت ابزارها.
2. تأیید → اجرا برای ابزار sensitive، و رد شدن ابزار read بدون نام سرور در پیام.
3. بستن برنامه: پایان یافتن زیرپروسه‌ها.
4. یک ایجنت نمونه با `/health` و `/ask` و ادامه‌ی job پس از ری‌استارت.
5. اندازه‌ی کاتالوگ روی Qwen 3.5 4B با `max_tools` کوچک.
