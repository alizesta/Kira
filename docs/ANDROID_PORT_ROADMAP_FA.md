# نقشه‌ی پورت اندروید Kira

## هدف

ساخت اپلیکیشن Native و مستقل Android در همان مخزن `alizesta/Kira`، با برابری قابلیت‌ها و رفتار مشترک با Windows. نسخه‌ی Android به اجرای دسکتاپ یا سرور شخصی نیاز ندارد.

## تصمیم‌های معماری

- Android: Kotlin + Jetpack Compose
- Windows: حفظ Python + PySide6
- قرارداد قابلیت‌ها: `shared/contracts/feature-parity.json`
- نگاشت قابلیت: Windows Game Mode ←→ Android AI Assistant
- داده‌ها و کلیدهای API: ذخیره‌سازی مستقل روی هر دستگاه
- منطق مشترک: قراردادها و رفتارهای مشخص؛ Adapterهای Native برای قابلیت‌های سیستم‌عامل

## فازها

### فاز ۱: پایه‌ی Native و AI Assistant
- ساخت Gradle project و پوسته‌ی Compose
- ناوبری بخش‌های Chat، Assistant، Route، Memory و Settings
- حباب شناور با اجازه‌ی صریح کاربر
- تعریف قرارداد هم‌ارزی قابلیت‌ها

### فاز ۲: موتور گفتگو و شخصیت‌ها
- انتقال رفتار گفتگو و استریم پاسخ
- پروفایل‌های Kira، Ren و Mika
- نشست و تاریخچه‌ی مجزای هر شخصیت
- اتصال به Route Manager اندروید

### فاز ۳: Route و حافظه
- Provider discovery و مدل‌ها
- اولویت‌بندی، Retry، Cooldown و Failover
- نگهداری مستقل کلیدها با Android Keystore
- حافظه‌ی کوتاه‌مدت و بلندمدت محلی

### فاز ۴: AI Assistant هوشمند
- دریافت محتوای صفحه با MediaProjection و رضایت کاربر در هر نشست
- پرسش درباره‌ی صفحه/اپلیکیشن فعال
- فرمان صوتی و پاسخ گفتاری
- دسترسی سریع شناور و چرخه‌ی عمر سرویس مطابق محدودیت‌های Android

### فاز ۵: قابلیت‌های مشترک دیگر
- ضمیمه‌ی عکس و فایل
- Shared Skills
- Ai1 Code با محیط کاری و محدودیت اجرای موبایل
- مدل‌های محلی سازگار با سخت‌افزار Android
- ابزارهای دستگاه با مجوزهای محدود و قابل توضیح

## قانون توسعه‌ی موازی

هر قابلیت جدید Windows باید شناسه‌ی مشترک داشته باشد و وضعیت Android آن در همان تغییر مشخص شود. پیاده‌سازی دو پلتفرم می‌تواند متفاوت باشد، اما نام، هدف، داده‌ها، جریان کار و نتیجه‌ی قابل مشاهده باید تا حد ممکن یکسان بماند.

قابلیت‌های غیرقابل‌انتقال مستقیم، مانند کنترل دسکتاپ یا اجرای PowerShell، باید با Adapter اندرویدی محدود و مشخص جایگزین شوند؛ نه اینکه با همان نام و رفتار غیرواقعی ارائه شوند.
