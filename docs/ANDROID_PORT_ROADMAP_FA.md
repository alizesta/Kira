# نقشه‌ی اندروید و هسته‌ی مشترک Kira

## هدف محصول

Kira یک محصول با دو کلاینت بومی است: Windows و Android. هر دو برنامه جداگانه نصب و اجرا می‌شوند، اما دو محصول یا دو مغز مستقل نیستند.

- یک Kira Core مشترک مسئول هوش، شخصیت‌ها، مکالمه، Route، حافظه، حساب و همگام‌سازی است.
- کلاینت Windows با Python/PySide6 و کلاینت Android با Kotlin/Jetpack Compose باقی می‌مانند.
- هر دو کلاینت از API یکسان استفاده می‌کنند و داده‌ی حساب‌محور را از همان سرور می‌گیرند.
- رابط و قابلیت‌های سیستم‌عامل بومی می‌مانند؛ نتیجه و رفتار قابلیت‌ها تا حد ممکن یکسان است.

## معماری هدف

```text
                    Kira Core Server
       ┌─────────────────────────────────────────┐
       │ Account / Identity / Session            │
       │ Shared Settings / Provider Credentials │
       │ Brain / Character Prompts / Route       │
       │ Chat History / Long-term Memory         │
       │ Sync / Backup / Attachments              │
       └────────────────────┬────────────────────┘
                            │ Kira Core API
                 ┌──────────┴──────────┐
                 │                     │
        Windows Client             Android Client
        Python / PySide6           Kotlin / Compose
        Windows adapters           Android adapters
        Local Ollama route         Device-local routes
        Game Mode                  AI Assistant
```

سرور مرجع اصلی داده‌های مشترک حساب است. کلاینت‌ها فقط Cache محلی و داده‌های مخصوص دستگاه را نگه می‌دارند.

## مالکیت داده

### اطلاعات مشترک حساب، روی Kira Core
- شناسه‌ی حساب و هویت‌های متصل
- تنظیمات مشترک Kira و شخصیت فعال
- Providerها، مدل‌های Cloud، اولویت Route، Failover و تنظیمات Brain
- مکالمه‌ها و تاریخچه‌ی هر شخصیت
- حافظه‌ی بلندمدت و خلاصه‌های مکالمه
- Shared Skills و ترجیحات مشترک
- نسخه و تاریخچه‌ی همگام‌سازی

### اطلاعات مخصوص هر دستگاه، روی همان دستگاه
- انتخاب میکروفون و خروجی صدا
- مجوزها و تنظیمات سیستم‌عامل
- مسیرها و دسترسی‌های فایل محلی
- تنظیمات ظاهری و اندازه‌ی پنجره
- مدل محلی و نشانی Ollama همان دستگاه
- وضعیت سرویس شناور، MediaProjection و ابزارهای بومی

Routeهای Cloud و تنظیماتشان حساب‌محورند. Route محلی مثل Ollama فقط در فهرست همان دستگاه قابل استفاده است و نباید یک آدرس localhost از ویندوز به گوشی منتقل شود.

## حساب کاربری و بازیابی اطلاعات

- در مرحله‌ی اول، حساب Kira با ایمیل و رمز عبور پشتیبانی می‌شود.
- شناسه‌ی داخلی حساب مستقل از روش ورود است.
- Google Sign-In بعداً به‌عنوان یک Identity Provider به همان حساب متصل می‌شود؛ اضافه‌شدن گوگل نباید حساب دوم بسازد یا تاریخچه را جدا کند.
- توکن نشست در Windows با حفاظت مخصوص ویندوز و در Android با Android Keystore نگهداری می‌شود.
- کلیدهای Provider روی سرور رمزنگاری‌شده ذخیره می‌شوند و از API خواندنی به کلاینت برگردانده نمی‌شوند.
- ورود با همان حساب روی دستگاه دیگر، تنظیمات مشترک، تاریخچه، شخصیت‌ها و حافظه را بازیابی می‌کند.

## انتقال اطلاعات نسخه‌ی فعلی ویندوز

در اولین اتصال حساب:
1. کلاینت اطلاعات موجود را فهرست و پیش‌نمایش می‌کند.
2. کاربر صریحاً انتقال داده را تأیید می‌کند.
3. تنظیمات مشترک، چت‌ها و حافظه به حساب منتقل می‌شوند.
4. Routeهای Cloud فقط با تأیید جداگانه‌ی انتقال کلیدها ثبت می‌شوند.
5. Routeهای محلی و تنظیمات مختص ویندوز به عنوان داده‌ی دستگاه باقی می‌مانند.
6. داده‌ی محلی تا تأیید موفقیت Sync حذف یا بازنویسی نمی‌شود.

## Kira Core API

قرارداد نسخه‌ی اول در shared/contracts/kira-core-api-v1.yaml تعریف می‌شود. مسئولیت Core:
- انتخاب شخصیت و ساخت System Prompt
- اجرای Brain و سیاست‌های ابزار
- خواندن حافظه‌ی حساب و تاریخچه
- انتخاب Route و اجرای Failover
- ذخیره‌ی پیام و نتیجه در حساب
- Sync تنظیمات و داده‌ها بین کلاینت‌ها

کلاینت نباید برای هر پاسخ مستقیماً Provider Cloud را صدا بزند. درخواست چت به Kira Core می‌رود تا هر دو پلتفرم دقیقاً از یک منطق استفاده کنند.

## نگاشت قابلیت‌های Native

- Windows Game Mode معادل قابلیت Android با نام AI Assistant است.
- Windows screen capture و Android MediaProjection Adapterهای جدا هستند، اما تصویر فقط با درخواست و تأیید کاربر در همان نشست دریافت می‌شود.
- ابزارهای دسکتاپ Windows روی Android عیناً اجرا نمی‌شوند؛ معادل بومی و محدود به مجوزهای Android دارند.
- Companion شناور ویندوز و حباب شناور Android رابط‌های متفاوت برای دسترسی به همان دستیارند.
