# تنظیمات صدا، Cloud Voice در Route و چیدمان تنظیمات

## ۱) فعال‌سازی هوشمند برنامه‌ها (`open_app`)
قبل از اجرای هر برنامه، Kira بررسی می‌کند نمونه‌ای از آن پنجره‌ی باز دارد یا نه:
- پنجره Minimize بود ← Restore می‌شود و جلو می‌آید.
- پشت پنجره‌های دیگر بود ← به جلو آورده می‌شود.
- اگر چند پنجره‌ی باز داشت (مثل Chrome) ← بالاترین پنجره‌ی غیر Minimize انتخاب می‌شود و نمونه‌ی جدید باز **نمی‌شود**.
- فقط اگر برنامه پنجره‌ی باز نداشت، نمونه‌ی جدید اجرا می‌شود.
- گزارش صادقانه است: اگر ویندوز اجازه‌ی گرفتن فوکوس ندهد، همین گفته می‌شود (نه «انجام شد»).
- شناسایی برنامه فقط به نام فرایند یا میان‌بر Start Menu محدود نیست؛ جزئیات در `docs/APP_LAUNCH_FA.md`. برنامه‌ای که در System Tray اجراست: اگر پنجره‌ی مخفی داشته باشد همان نمایش داده می‌شود، وگرنه یک‌بار اجرای عادی داده می‌شود تا خود برنامه نمونه‌ی در حال اجرا را بالا بیاورد.

## ۲) جلوگیری از نشت متن داخلی مدل
فیلتر مرکزی `kira/leak_guard.py` روی خروجی همه‌ی Routeها (چت، صدا و ابزارها) کار می‌کند:
- تگ‌های `<think>`، `<thinking>`، `<reasoning>`، `<analysis>`، `<scratchpad>` و کانال‌های Harmony (`analysis`) حذف می‌شوند.
- مقدمه‌ی تحلیلیِ بدون تگ («Thinking Process: …»، «The user is asking …»، «کاربر می‌خواهد …») تا شروع پاسخ واقعی نگه داشته می‌شود؛ شروع پاسخ واقعی: خط «Final answer:/پاسخ نهایی:»، خط برچسب احساس مثل `[smug:70]`، بلوک ابزار/برنامه، یا (وقتی تحلیل انگلیسی بوده) اولین خط فارسی.
- خطوط یادداشت سیستم/Router که مدل در جواب تکرار کرده (`[System note …]`، `[Route …]`) نمایش داده و خوانده نمی‌شوند.
- اگر مدل فقط تحلیل برگرداند، چیزی نمایش داده نمی‌شود و Router همان درخواست را به Route بعدی می‌دهد (پاسخ نهایی دوباره از مدل دیگر گرفته می‌شود).
- Tool Calling و Planning مختل نمی‌شوند: بلوک‌های `<kira_tool>` و `<kira_plan>` همیشه رد می‌شوند.
- صدا فقط متن تمیزشده را می‌خواند.

## ۳) تنظیمات صدا (تب «صدا و میکروفون»)
هر تغییر در این تب بعد از لحظه‌ای خودکار و دائمی ذخیره می‌شود.
- **خروجی:** سرعت، زیر و بمی، سبک بیان، شدت سبک، بلندی خروجی، انتخاب بلندگو/هدفون.
- **ورودی:** انتخاب میکروفون، بلندی میکروفن (٪)، حساسیت.
- بلندی خروجی و بلندی میکروفن کاملاً مستقل‌اند.
- فقط گزینه‌هایی نمایش داده می‌شوند که یکی از موتورهای فعال واقعاً پشتیبانی می‌کند (تیپ روی هر گزینه موتورش را می‌گوید):

| موتور | سرعت | زیر و بمی | سبک بیان |
|---|---|---|---|
| Edge (محلی) | ✓ | ✓ | — |
| Windows (محلی) | ✓ | — | — |
| ElevenLabs | ✓ (مدل‌های Turbo/Flash/Multilingual) | — | ✓ (فقط Multilingual v2، با «شدت سبک») |
| Google AI Studio | — | — | ✓ (از طریق دستور سبک در متن) |
| Groq | — | — | — |

بلندی خروجی با پخش‌کننده‌ی خود Kira اعمال می‌شود و همیشه کار می‌کند.

## ۴) Cloud Voice در بخش Route
بخش Route حالا دو نما دارد: «مدل‌های چت» و «صدا (Cloud Voice)». نمای صدا همان مدیریت قبلی Cloud Voice است (بدون سیستم موازی): فعال/غیرفعال‌کردن Provider، چند API Key برای هر Provider، اعتبارسنجی و وضعیت اتصال/خطا، انتخاب مدل و صدا، اولویت و Fallback (Cloud ← Edge ← Windows). تب جدا حذف شد و دکمه‌ی «مدیریت Providerهای صدا…» در تب صدا مستقیم به همین نما می‌رود. تنظیمات و کلیدهای صدا همچنان جدا از مدل‌های چت ذخیره می‌شوند (`cloud_voice.json`).

## ۵) چیدمان تنظیمات
فیلدهای عددی، انتخابگرها و اسلایدرها عرض متناسب با محتوایشان دارند و تا ته پنجره کشیده نمی‌شوند؛ فیلدهای متنی بلند (کلید، آدرس، نام مدل) جای کافی دارند. فاصله‌ها کمی فشرده‌تر شده‌اند.

## کلیدهای جدید در settings.json
`voice_style`، `voice_style_degree`، `output_device`، `mic_device`، `mic_gain`.
