# Audio Manager (مدیریت صدای ویندوز)

ماژول صدا بخشی از Windows Control Layer است (`AudioModule` در `kira/tools/winmodules.py`، کد در `kira/tools/audio.py`). به هیچ Provider/مدلی وابسته نیست، Hybrid Brain و Tool Registry تغییر نکردند و همه‌ی قانون‌های امنیتی لایه (سطح ریسک، درخواست صریح، ثبت در Journal) برقرار است.

## ابزارها

| ابزار | سطح | کار |
|---|---|---|
| `audio_get_volume` | READ | ولوم واقعی (٪)، وضعیت Mute، خروجی و ورودی پیش‌فرض |
| `audio_set_volume(percent)` | ACTION | ولوم را روی عدد دقیق ۰ تا ۱۰۰ می‌گذارد |
| `audio_change_volume(direction, amount)` | ACTION | `up`/`down` به اندازه‌ی `amount` واحد درصد (پیش‌فرض ۱۰) |
| `audio_mute` / `audio_unmute` | ACTION | Mute و Unmute بلندگو/خروجی |
| `audio_list_apps` | READ | برنامه‌های دارای جلسه‌ی صدا (Volume Mixer) با ولوم، Mute و «در حال پخش»؛ بازی‌های محتمل علامت می‌خورند |
| `audio_set_app_volume(app, percent)` | ACTION | ولوم یک برنامه |
| `audio_change_app_volume(app, direction, amount)` | ACTION | کم/زیاد کردن ولوم یک برنامه |
| `audio_set_app_mute(app, muted)` | ACTION | Mute/Unmute یک برنامه |
| `audio_list_devices(kind)` | READ | دستگاه‌های خروجی/ورودی (فعال و جداشده) و پیش‌فرض فعلی هر دو |
| `audio_set_default_device(kind, device)` | ACTION | خروجی یا ورودی پیش‌فرض ویندوز را عوض می‌کند |

ابزارهای ACTION فقط وقتی اجرا می‌شوند که **پیام فعلی کاربر** درخواست صریح تغییر را داشته باشد (مثلاً «صدا» + «ببر/بذار/کم کن»، «Mute کن»، «هدفون» + «بذار»). اگر مدل خودش تصمیم بگیرد ولی پیام کاربر آن را نخواسته باشد، ابزار رد می‌شود، چیزی تغییر نمی‌کند و رد شدن در Journal ثبت می‌شود. پرسش‌هایی مثل «صدا چنده؟» فقط ابزار خواندنی را فعال می‌کنند.

## روش و تأیید نتیجه
- API: Windows Core Audio (`IMMDeviceEnumerator`، `IAudioEndpointVolume`، `IAudioSessionManager2`، `ISimpleAudioVolume`)، همان‌هایی که اسلایدر ولوم و Volume Mixer ویندوز می‌خوانند. از طریق Windows PowerShell 5.1 و **یک اسکریپت ثابت** (کلاس C# با `Add-Type`) اجرا می‌شود. **وابستگی پایتونِ تازه‌ای اضافه نشد**؛ `requirements.txt` عوض نشد (PowerShell 5.1 و .NET Framework بخشی از Windows 10/11 هستند).
- تغییر دستگاه پیش‌فرض: ویندوز API رسمی ندارد؛ از رابط `IPolicyConfig` استفاده می‌شود (همان که SoundSwitch، EarTrumpet و AudioDeviceCmdlets استفاده می‌کنند). نقش‌های Console، Multimedia و Communications هر سه ست می‌شوند.
- **بعد از هر تغییر وضعیت واقعی دوباره خوانده می‌شود** (با شیءهای COM تازه، تا حدود ۱.۵–۳ ثانیه صبر). نتیجه فقط وقتی «موفق» گزارش می‌شود که مقدار واقعی با درخواست بخواند (برای ولوم ±۱٪ گرد کردن درایور پذیرفته می‌شود). در غیر این صورت خطا همراه با وضعیت واقعی برمی‌گردد.
- امنیت: متن کاربر/مدل هرگز وارد اسکریپت نمی‌شود. داده در یک متغیر محیطی JSON (`KIRA_AUDIO_REQ`) می‌آید. عدد‌ها بازه‌بندی می‌شوند، `op` و `mode` از فهرست بسته‌اند، شناسه‌ی دستگاه همیشه همان است که خود ویندوز گزارش داده (نه حرف مدل) و شناسه‌ی جلسه‌ها از فهرست زنده می‌آید. اجراکننده‌ی مشترک: `kira/tools/winrunner.py`.

## نمونه‌ها
- «صدای ویندوز الان چنده؟» ← `audio_get_volume`
- «صدا رو ببر روی ۵۰ درصد» ← `audio_set_volume(percent=50)`
- «صدا رو ۲۰ درصد کم کن» ← `audio_change_volume(direction=down, amount=20)` (۲۰ واحد درصد از ولوم فعلی، مثلاً ۷۰٪ ← ۵۰٪)
- «سیستم رو Mute کن» / «Unmute کن» ← `audio_mute` / `audio_unmute`
- «صدای دیسکورد رو کم کن» ← `audio_change_app_volume(app=Discord, direction=down)`
- «صدای بازی رو کم کن» ← فقط اگر دقیقاً یک برنامه‌ی «احتمالاً بازی» صدا داشته باشد؛ وگرنه نام را می‌پرسد.
- «صدای خروجی رو بذار روی هدفون» ← `audio_set_default_device(kind=output, device=هدفون)`
- «دستگاه‌های ورودی صدا رو نشون بده» ← `audio_list_devices(kind=input)`

## تشخیص برنامه و دستگاه (بدون حدس)
- نام برنامه با نام فرایند و نام نمایشی جلسه تطبیق داده می‌شود. نام‌های رایج فارسی/انگلیسی (مرورگر، کروم، دیسکورد، اسپاتیفای، موسیقی ...) نگاشت دارند. اگر چند برنامه جور باشد، تغییری نمی‌دهد و از کاربر می‌پرسد.
- «بازی» یعنی برنامه‌ای که مسیر فایل اجرایی‌اش در پوشه‌های رایج بازی است (`steamapps\common`، Epic Games، Riot Games، GOG، Xbox، EA، Ubisoft، Battle.net و `\Games\`). مسیر فقط برای همین علامت استفاده می‌شود و به مدل نمی‌رسد.
- دستگاه با نام کامل، بخشی از نام یا نوع (هدفون، هدست، اسپیکر، مانیتور/HDMI، میکروفون؛ بر اساس Form Factor ویندوز) پیدا می‌شود. دستگاه جداشده/غیرفعال انتخاب نمی‌شود و خطا می‌گوید که ثبت است ولی متصل نیست.

## خطاهای شناخته‌شده و پیام‌ها
دستگاه خروجی/ورودی فعال نیست، دستگاه همان لحظه قطع شد، دسترسی رد شد، سرویس Windows Audio خاموش است، دستگاه کنترل ولوم نرم‌افزاری ندارد (بعضی HDMI/S/PDIF)، برنامه جلسه‌ی صدا ندارد، جلسه در حین کار بسته شد، `Add-Type` توسط AppLocker/Constrained Language Mode بسته است: هر کدام پیام واضح و علت واقعی می‌دهد و چیزی «موفق» گزارش نمی‌شود.

## محدودیت‌ها
- **آزموده نشده:** هیچ تستی (قدیمی یا جدید) اجرا نشد و کد C# اینجا کامپایل نشد؛ فقط بازبینی ایستا و بررسی نحو پایتون. اولین اجرا روی ویندوز واقعی آزمون واقعی است. اگر کامپایل اسکریپت شکست بخورد، ابزار خطای `Add-Type` را همراه جزئیات برمی‌گرداند و چیزی تغییر نمی‌دهد.
- هر فراخوانی PowerShell و کامپایل C# حدود ۱ تا ۳ ثانیه طول می‌کشد.
- کنترل ولوم/Mute فقط روی **خروجی پیش‌فرض** است؛ کنترل ولوم یا Mute میکروفون پیاده نشد (فقط فهرست و تغییر ورودی پیش‌فرض).
- ولوم برنامه‌ها برای جلسه‌های دستگاه‌های خروجی فعال است؛ برنامه‌ای که هنوز صدا پخش نکرده در Volume Mixer ویندوز هم دیده نمی‌شود. برنامه‌ی چندجلسه‌ای (مثل مرورگر) همه‌ی جلسه‌هایش با هم تغییر می‌کند. جلسه‌ای که بعداً ساخته شود تغییر نمی‌گیرد.
- تغییر مسیر خروجی هر برنامه به دستگاه دیگر (App volume and device preferences ویندوز) پشتیبانی نمی‌شود.
- تشخیص «بازی» حدسی و بر پایه‌ی مسیر نصب است؛ بازی‌ای که جای دیگر نصب شده علامت نمی‌خورد (نامش را بگو).
- `IPolicyConfig` رابط رسمی نیست و ممکن است در نسخه‌ی بعدی ویندوز تغییر کند.
- Journal در حافظه است و با بستن برنامه پاک می‌شود (مثل بقیه‌ی لایه).
