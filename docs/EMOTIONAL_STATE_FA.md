# سامانه‌ی احساسی چندلایه‌ی Kira

## هدف

وضعیت احساسی Kira از شخصیت پایه و رفتار ثابت او جداست. سیستم سه محور مستقل را نگه می‌دارد:

1. **Emotion / Mood:** احساس غالب و احساسات همراه، با شدت ۰ تا ۱۰۰.
2. **Conversational Energy:** انرژی شبیه‌سازی‌شده‌ی مکالمه؛ مستقل از احساس و مستقل از خستگی کاربر.
3. **Behavioral Disposition:** سبک ابراز احساس، مثل بازیگوش، حمایتگر، کم‌حرف، لجباز یا قهرکرده.

این سیستم شبیه‌سازی شخصیتی است، نه ادعای داشتن وضعیت زیستی یا احساس واقعی.

## احساسات

کتابخانه‌ی جاری ۲۶ شناسه دارد: ۲۴ حالت قبلی به‌علاوه‌ی `fearful` و `disgusted`. فهرست مرجع در `kira/mood.py` و نگاشت واکنش‌های آواتار در `emotion_library/emotions.json` قرار دارد.

- احساسات در فایل `kira_mood.json` داخل `DATA_DIR` ذخیره می‌شوند.
- نیمه‌عمر افت شدت احساسات ۱۵ دقیقه است.
- `playful` و `affectionate` حداقل امتیاز استراحت دارند تا شخصیت در حالت پایه کاملاً بی‌روح نشود.
- پاسخ‌های خود Kira نیز با تگ احساسی‌شان وضعیت را به‌روزرسانی می‌کنند.

## انرژی مکالمه

- مقدار آغازین: ۷۸ از ۱۰۰
- هزینه‌ی پیام کاربر: ۰٫۵۵
- هزینه‌ی پاسخ Kira: ۰٫۳۵
- بازیابی در زمان عدم فعالیت: ۰٫۰۰۲۲ امتیاز در ثانیه، تا سقف ۱۰۰

سطوح: exhausted، tired، low، normal، active و hyper. انرژی فقط روی ریتم و طول پاسخ اثر می‌گذارد و نباید دقت یا کیفیت پاسخ را کاهش دهد.

## تمایل رفتاری

تمایل رفتاری با نیمه‌عمر ۴۰ دقیقه به‌صورت جداگانه افت می‌کند. رفتارهای پایه شامل playful، affectionate، teasing و sarcastic هستند. رویدادهای مکالمه می‌توانند رفتارهای quiet، protective، focused، sulking، stubborn، clingy، cheerful، reserved، flirty و tsundere را تقویت یا تضعیف کنند.

نمونه:
- پیام ناراحت‌کننده‌ی کاربر: quiet + affectionate + protective
- شوخی کاربر: playful + teasing
- عذرخواهی: affectionate تقویت و sulking/stubborn تضعیف می‌شود
- اشاره‌ی حسادت‌برانگیز: sulking + clingy + stubborn

رفتارها دستور مطلق نیستند؛ امتیازهای مستقل‌اند و در کنار احساسات فعال تفسیر می‌شوند.

## رابط‌های کد

- `on_user_message(text, now)`: رویدادهای پیام کاربر، رفتار و انرژی را به‌روزرسانی می‌کند.
- `on_reply(emotions, intensity, now)`: احساس تگ‌شده‌ی پاسخ Kira و تمایل رفتاری را ذخیره می‌کند.
- `current(now)`: snapshot سازگار با API قبلی، همراه با فیلدهای جدید `secondary_emotions`، `energy`، `energy_label`، `behaviors` و `dominant_behavior`.
- `build_block(mode_name)`: متن مشترک برای system prompt همه‌ی Providerها می‌سازد. حالت strict هیچ داده‌ی مود را افشا نمی‌کند؛ task فقط زمینه‌ی مهم برای نحوه‌ی پاسخ‌گویی را اضافه می‌کند.

## سازگاری و تست

فایل‌های قدیمی `kira_mood.json` که فقط `scores` داشتند همچنان خوانده می‌شوند؛ فیلدهای جدید با مقدار پیش‌فرض ساخته می‌شوند. هیچ تغییری در Route Manager یا انتخاب Provider انجام نشده است.

تست‌ها: `python -m unittest discover -s tests -p "test_mood.py"`
