# API Manager (صفحه‌ی Route)

باز کردن: منوی ☰ ← **Route**. بالای صفحه سه بخش است: **Add API**، **Registered APIs**، **API Details**؛ زیر آن‌ها همان **Routeها** (مدل‌ها و اولویت اجرا) و Ollama محلی.

## افزودن API
فقط API Key را بزن و **Add** را بزن. Kira خودش:
1. شکل کلید را بررسی می‌کند (بدون درخواست شبکه).
2. از endpoint رسمی «فهرست مدل‌ها»ی همان سرویس می‌پرسد (همین یک درخواست هم اعتبارسنجی است هم فهرست مدل‌ها؛ درخواست تکراری نمی‌فرستد).
3. اگر دقیقاً یک سرویس تأیید کرد، ثبتش می‌کند؛ وگرنه **چیزی ثبت نمی‌شود** و دلیل نمایش داده می‌شود: `Invalid` (نامعتبر)، `Ambiguous` (چند سرویس)، Unknown (هیچ‌کدام).

کلید به سرویس‌هایی که نمی‌تواند مال آن‌ها باشد فرستاده نمی‌شود: پیشوند `gsk_` ← فقط Groq؛ پیشوند `AIza` ← فقط Google AI Studio؛ کلید بدون پیشوند شناخته‌شده ← فقط Mistral و Cloudflare (که کلیدشان پیشوند ندارد).

**Cloudflare:** اگر توکن اجازه‌ی خواندن Accounts داشته باشد Account ID خودکار پیدا می‌شود؛ وگرنه Kira می‌گوید و کادر Account ID را پر می‌کنی (توکن‌های «Account API Token» همیشه Account ID می‌خواهند).

بعد از ثبت، مدل پیش‌فرض همان سرویس (اگر واقعاً در فهرست بود) روشن می‌شود؛ بقیه‌ی مدل‌ها در **API Details** هستند و با تیک روشن می‌شوند.

## Registered APIs
ستون‌ها: Provider (با آخرین ۴ نویسه‌ی کلید) · API Status · مدل‌های قابل‌دسترسی · مدل‌های فعال · آخرین اعتبارسنجی · اولویت · فعال.
دکمه‌ها: **View Details**، **Refresh / Rediscover Models**، **Edit** (کلید جدید اول اعتبارسنجی می‌شود؛ اگر نامعتبر بود کلید قبلی دست‌نخورده می‌ماند)، **Enable / Disable**، **Delete**، ▲▼ (اولویت کل API).
- Groq/Mistral/Cloudflare ساخته‌شده در برنامه حذف‌شدنی نیستند؛ «Delete» کلید را پاک و Routeهایشان را غیرفعال می‌کند. APIهای افزوده‌شده با Routeهایشان حذف می‌شوند.
- کلید دوم از همان سرویس یک API اضافی می‌شود («Groq (2)»). مدلِ یکسان روی چند کلید در جزئیات یک مدل است («روی API دیگر هم») ولی Routeهایش برای Failover جدا می‌ماند.
- ▲▼ فقط جای APIهای ثبت‌شده را عوض می‌کند؛ ترتیب مدل‌های هر API و جای Ollama عوض نمی‌شود.

## API Details
هر مدل: وضعیت (✓ در دسترس / ✕ دیگر در دسترس نیست / Unknown)، Context Window، Max Output، Text/Vision/Tool Calling، و تیک فعال. **هرچه Provider نگفته باشد `Unknown` یا `Not Available` است؛ هیچ عددی حدس زده نمی‌شود.** Token Usage و Remaining Quota برای هیچ‌یک از چهار سرویس از طریق کلید قابل‌دریافت نیست و `Not Available` نمایش داده می‌شود. Rate Limit فقط وقتی نمایش داده می‌شود که سرویس در پاسخ آخرین بررسی هدرهای `x-ratelimit-*` فرستاده باشد.

## مهاجرت از نسخه‌ی قبل
کلیدها، Routeها، اولویت‌ها، مدل‌های انتخابی و Cooldownها همان‌جا که بودند می‌مانند؛ هیچ‌چیز دوباره وارد نمی‌شود. APIهای قدیمی با وضعیت «هنوز اعتبارسنجی نشده» نمایش داده می‌شوند (راه‌اندازی هیچ درخواست شبکه‌ای نمی‌فرستد)؛ با Refresh اعتبارسنجی می‌شوند. وضعیت APIها در `api_registry` داخل `settings.json` (خارج از پوشه‌ی برنامه) ذخیره می‌شود و کلید ندارد؛ کلیدها مثل قبل با DPAPI رمزنگاری می‌شوند.
