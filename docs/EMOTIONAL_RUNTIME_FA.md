# معماری موتور احساسی Kira

## اصل طراحی
موتور احساسی مستقل از Provider و مدل زبانی است. مدل می‌تواند احساس پیشنهادی برای یک پاسخ را با تگ اعلام کند، اما وضعیت پایدار، شدت، افت تدریجی، رابطه و حافظه را خود Kira محاسبه می‌کند.

## لایه‌ها
- **Emotion:** احساسات لحظه‌ای و ماندگار با شدت ۰ تا ۱۰۰ و افت تدریجی مستقل.
- **Behavior:** سبک ارائه‌ی پاسخ؛ مثل playful، teasing، gentle، quiet، stubborn و focused. رفتار با احساس یکی نیست.
- **Energy:** ظرفیت مکالمه، هزینه‌ی تعامل و بازیابی در زمان بی‌فعالیتی.
- **Relationship:** trust، closeness، familiarity، comfort و tension. تغییرات کوچک و تدریجی‌اند و برای تنبیه یا ایجاد وابستگی طراحی نشده‌اند.
- **Emotional memory:** فقط رویدادهای با سیگنال احساسی قوی ذخیره می‌شوند؛ تاریخچه‌ی کوتاه رویدادها نیز جدا نگه داشته می‌شود.
- **Events:** رویدادهای برنامه و آواتار، بدون وابستگی به Route یا Provider، به Runtime گزارش می‌شوند.
- **Director/Avatar:** EmotionDirector همچنان مسئول انیمیشن فریم‌به‌فریم است؛ Runtime وضعیت پایدار را فراهم می‌کند و آواتار از snapshot آن واکنش می‌گیرد.

## ذخیره‌سازی و سازگاری
فایل جدید در DATA_DIR با نام `kira_emotional_state.json` ذخیره می‌شود. اولین بار، state قدیمی `kira_mood.json` به‌صورت محافظه‌کارانه وارد می‌شود. فایل قدیمی حذف یا بازنویسی نمی‌شود.

## قراردادها
- هیچ API key یا اطلاعات حساس در حافظه‌ی احساسی ذخیره نمی‌شود.
- شکست Runtime نباید چت را متوقف کند.
- حالت strict هیچ context احساسی به prompt اضافه نمی‌کند.
- ترکیب و تعارض احساسات از Emotion Library مشترک با Avatar Engine خوانده می‌شود.
- Route Manager و Providerها هیچ اختیار مستقیمی برای تغییر شخصیت ندارند.

## پیوستگی احساسی در مکالمه
- متن آخرین پیام کاربر به همان Runtime فعلی داده می‌شود تا خاطرات احساسی مرتبط با موضوع بازیابی شوند.
- وقتی موضوع مشخص است، خاطره‌ی بدون هم‌پوشانی موضوعی وارد prompt نمی‌شود؛ در نبود query، رفتار قبلی مبتنی بر اهمیت و تازگی حفظ می‌شود.
- متن پاسخ Kira همراه با تگ احساسی به Runtime می‌رسد؛ فقط پاسخ‌های دارای احساس منفیِ قوی به‌عنوان خاطره‌ی احساسی ثبت می‌شوند.
- snapshot ساختاریافته منبع اصلی وضعیت، انرژی و رفتار در prompt است؛ راهنمای قدیمی فقط توصیف تکمیلی و سیگنال موقعیتی را اضافه می‌کند تا دو snapshot متناقض ساخته نشود.
- تگ احساسی در ابتدای استریم فقط حالت احساسی آواتار را اعمال می‌کند؛ پایان پاسخ فقط پس از اتمام استریم ثبت می‌شود.
- توقف عمدی یا شکست تولید، رویداد شروع پاسخ و احساس نیمه‌کاره را پاک می‌کند؛ رویداد شکست همچنان واکنش خطای خودش را دارد.

## محدودیت‌های فعلی
تشخیص حالت کاربر هنوز عمدتاً بر اساس قواعد محلی و متن است، نه تحلیل عمیق چندوجهی. Relationship و energy مدل‌های سبک و قابل تنظیم‌اند، نه ادعای شبیه‌سازی روان‌شناسی انسان. نمایش گرافیکی کامل همه‌ی لایه‌ها در پنل تنظیمات و انیمیشن‌های اختصاصی برای تمام احساسات، کار تکمیلی بعدی است.

- پیام ناقص، لغوشده یا قطع‌شده به حافظه‌ی شخصیت و حافظه‌ی احساسی آموزش داده نمی‌شود؛ پاسخ‌های محلی ثابت نیز voice/mood را تغییر نمی‌دهند.
- خاطرات احساسی دارای speaker provenance هستند، query بدون token مؤثر چیزی بازیابی نمی‌کند و خاطرات پس از بازه‌ی نگهداری از recall خارج می‌شوند.
- رکوردهای خراب حافظه هنگام بارگذاری اعتبارسنجی می‌شوند و خطاهای به‌روزرسانی mood در log ثبت می‌شوند.
