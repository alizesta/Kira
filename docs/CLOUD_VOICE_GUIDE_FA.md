# راهنمای Cloud Voice

تب **Cloud Voice** (زیر «صدا و میکروفون») برای تشخیص گفتار (STT) و تبدیل متن به گفتار (TTS) با سرویس‌های ابری است. این مدل‌ها **جدا از Route Manager** هستند؛ Route فقط برای مدل‌های چت است و مدل‌های صوتی (whisper، orpheus، scribe، `*-tts`) هرگز در آن دیده نمی‌شوند.

## شروع
1. در بخش هر Provider دکمه‌ی **Add API Key** را بزن، کلید را وارد کن. کلید همان لحظه اعتبارسنجی می‌شود و مدل‌ها و قابلیت‌هایش از خودِ Provider خوانده می‌شود.
2. در بخش STT و TTS «از … ابری استفاده شود» را روشن کن، ترتیب Providerها را با ▲▼ بچین و مدل/صدا را انتخاب کن.
3. تغییرها همان لحظه ذخیره می‌شوند (نیازی به «ذخیره تنظیمات» نیست).

## چه چیزی از هر Provider خوانده می‌شود
| Provider | STT | TTS |
|---|---|---|
| Groq | مدل‌های `whisper-*` از فهرست مدل‌های خودِ Groq | مدل‌های Orpheus از همان فهرست؛ فقط انگلیسی و عربی (فارسی به سرویس بعدی می‌رود) |
| Google AI Studio | مدل‌های Gemini که ورودی صوتی می‌گیرند (از فهرست مدل‌ها) | مدل‌های `*-tts` از همان فهرست |
| ElevenLabs | Scribe (ElevenLabs این مدل‌ها را در API فهرست نمی‌کند؛ فهرست داخلی، با برچسب) | مدل‌ها و زبان‌هایشان از `/v1/models`، صداها از `/v1/voices` |
| MiniMax | — | مدل‌های `speech-2.8-turbo` و `speech-2.8-hd` از فهرست داخلی؛ اعتبارسنجی با یک درخواست کوتاه واقعی TTS؛ صدای پیش‌فرض `female-shaonv` و امکان واردکردن Voice ID دلخواه |

قابلیتی که با کلیدهای فعلی پشتیبانی نشود، قابل فعال‌کردن نیست (تیک غیرفعال و توضیح علت در Tooltip).

## چند کلید برای یک Provider
- هر کلید نام، کلید فعال/غیرفعال، وضعیت و جای مستقل در ترتیب دارد.
- اگر یک مدل از چند کلید شناسایی شود، **فقط یک‌بار** نمایش داده می‌شود و کنارش تعداد کلیدها می‌آید؛ درخواست‌ها به ترتیب کلیدها می‌روند.
- خطای 429 / سهمیه: همان کلید تا زمان `Retry-After` خودِ Provider (یا ۳۰ ثانیه برای محدودیت نرخ، یک ساعت برای تمام‌شدن سهمیه) کنار گذاشته می‌شود و کلید بعدی امتحان می‌شود. کلید نامعتبر هم «نامعتبر» علامت می‌خورد.
- سهمیه‌ها جمع زده نمی‌شوند و هر کلید همان محدودیتی را دارد که Provider برایش گذاشته. استفاده از چند حساب برای دور زدن محدودیت‌ها ممکن است شرایط استفاده‌ی Provider را نقض کند؛ مسئولیتش با خود توست.

## Failover
MiniMax از API جهانی `https://api.minimax.io/v1/t2a_v2` استفاده می‌کند. مدل‌ها و Voice IDهای حساب از endpoint فهرست نمی‌شوند؛ مدل‌های شناخته‌شده به‌صورت کاتالوگ نمایش داده می‌شوند و کلید با یک درخواست کوتاه واقعی اعتبارسنجی می‌شود. این درخواست مقدار کمی از سهمیه TTS مصرف می‌کند. صدای دلخواه را می‌توان در فیلد Voice ID وارد کرد.

ترتیب: Providerها به ترتیب تو → کلیدهای هر Provider → در آخر موتور محلی (STT: Whisper محلی، TTS: صدای Edge و بعد صداهای ویندوز). خطای شبکه/سرور Provider باعث رفتن مستقیم به Provider بعدی می‌شود (کلیدها بی‌دلیل امتحان نمی‌شوند).

## کجا ذخیره می‌شود
`%LOCALAPPDATA%\Kira\cloud_voice.json` (بیرون از پوشه‌ی برنامه، کنار `settings.json`). کلیدها با Windows DPAPI رمز می‌شوند. تنظیمات Route هم در `settings.json` همان پوشه است. با عوض‌کردن پوشه‌ی برنامه چیزی از بین نمی‌رود و فایل در پشتیبان‌های خودکار هم کپی می‌شود.
