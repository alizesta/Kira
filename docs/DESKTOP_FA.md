# تعامل با دسکتاپ (T5-B)

کد: `kira/tools/desktop.py`، دامنه‌ی `desktop` در Windows Control Layer. بدون وابستگی جدید (ctypes + یک اسکریپت ثابت PowerShell برای UI Automation).

## ابزارها
| ابزار | سطح | کار |
|---|---|---|
| `window_list`، `window_active` | خواندن | پنجره‌های باز با شناسه‌ی `hwnd:N` و پنجره‌ی فعال |
| `window_focus` | ۲ | آوردن پنجره به جلو (و بررسی اینکه واقعاً جلو آمد) |
| `window_close` | ۲ | بستن مؤدبانه (مثل ضربدر؛ اگر برنامه می‌پرسد ذخیره شود، Kira نمی‌گوید بسته شد) |
| `window_set_state` | ۲ | کوچک / بزرگ / برگرداندن، با بررسی بعد از کار |
| `type_text` | ۲ | تایپ متن (حداکثر ۲۰۰۰ نویسه) با SendInput یونیکد (فارسی هم) |
| `press_keys` | ۲ | یک کلید یا میانبر مجاز (enter, tab, esc, جهت‌ها، ctrl+s/c/v/x/a/z/y/f ...) |
| `clipboard_set` | ۲ | گذاشتن متن در کلیپ‌بورد و خواندن دوباره برای اطمینان |
| `clipboard_get` | ۳ (تأیید) | خواندن کلیپ‌بورد (کلید/رمز در آن پنهان می‌شود) |
| `ui_list_controls` | خواندن | دکمه‌ها، منوها، فیلدها و چک‌باکس‌های یک پنجره با نام |
| `ui_click` | ۲ | کلیک روی یک کنترل با نام (Invoke/Toggle/Select/Expand) |
| `ui_click_confirmed` | ۳ (تأیید) | همان، برای کنترل‌های حذف/ارسال/پرداخت/ورود/نصب/اجازه |
| `ui_set_text` | ۲ | پر کردن فیلد متنی با ValuePattern؛ مقدار بعد از نوشتن دوباره خوانده و مقایسه می‌شود |
| `mouse_click` | ۳ (تأیید) | کلیک روی نقطه‌ی خام داخل پنجره (فقط وقتی کنترل نام‌دار نیست) |

## قواعد امنیتی (در کد)
- پنجره از حرف کاربر پیدا می‌شود (عنوان، نام برنامه، «مرورگر»، `hwnd:N`). اگر چند پنجره جور بود، Kira باید دقیق‌تر انتخاب کند؛ حدس نمی‌زند.
- **قبل از هر ورودی** پنجره جلو آورده و تأیید می‌شود؛ تایپ طولانی هر ۴۰ نویسه دوباره بررسی می‌کند و اگر پنجره‌ی فعال عوض شد **متوقف** می‌شود.
- ورودی هرگز به این‌ها نمی‌رود: خود Kira، ترمینال/PowerShell/cmd/WSL، mshta/اسکریپت، regedit/mmc/taskmgr، پنجره‌ی Run، UAC و امنیت ویندوز، پنجره‌هایی که عنوانشان ورود/رمز/احراز هویت است، برنامه‌های مدیریت رمز. (تایپ در ترمینال = اجرای دستور دلخواه.)
- فهرست کلیدها بسته است: بدون کلید Windows، بدون Alt+F4 (برای بستن `window_close`)، بدون Ctrl+Alt+Del / Ctrl+Shift+Esc.
- فیلد رمز (`IsPassword`) هرگز خوانده یا پر نمی‌شود؛ متنی که شبیه کلید/رمز باشد تایپ نمی‌شود.
- اسکریپت UI Automation ثابت است و ورودی‌ها به‌صورت JSON در متغیر محیطی می‌روند، نه داخل کد.
- نتیجه‌ی تایپ/کلیک/کلید **قابل بررسی خودکار نیست** و Kira همین را می‌گوید؛ فقط بستن پنجره، تغییر اندازه، کلیپ‌بورد و `ui_set_text` بعد از کار دوباره بررسی می‌شوند.

## محدودیت‌ها
- برنامه‌ای که با Administrator اجرا شده، ورودی از Kira (غیر Admin) نمی‌پذیرد؛ خطا گزارش می‌شود.
- بعضی برنامه‌ها (بازی‌ها، برنامه‌های با رندر اختصاصی) UI Automation ندارند؛ فقط `mouse_click` باقی می‌ماند.
- ساخت Word و کار با منوهای Office: T5-C؛ صدا و روشنایی: T5-D (صدا از قبل هست).

## نیاز به اعتبارسنجی روی Windows 11 (هیچ‌کدام اینجا اجرا نشده)
1. Notepad: «نوت‌پد را باز کن و این متن فارسی را بنویس» → متن درست و راست‌به‌چپ.
2. `ui_list_controls` روی Notepad و Calculator؛ `ui_click` روی دکمه‌ها؛ `ui_set_text` روی فیلد جست‌وجو.
3. `window_close` روی Notepad با متن ذخیره‌نشده (باید بگوید هنوز باز است).
4. مرورگر: دو پنجره‌ی Chrome → درخواست «مرورگر را ببند» باید hwnd بخواهد.
5. تایپ در PowerShell / Run / پنجره‌ی ورود باید رد شود.
6. زمان اجرای اسکریپت UIA روی پنجره‌های سنگین (مرورگر)، سقف ۲۰ ثانیه.
